# Kode Dot virtual I²C board part

This WebAssembly part is loaded by ESP-EMU's official `CosimPump`. It models the I²C devices needed to bring up the KodeOS display/input path:

- **TCA6408A** at `0x20`, on I²C0 GPIO5 (SCL) / GPIO4 (SDA). It models the register banks, active-low button inputs, touch interrupt bit, panel-power output and active-low IRQ on GPIO6.
- **CST820** at `0x15`, on the same bus. It reports the CST8xx-family ID expected by the pinned SDK and exposes a six-byte touch frame. Browser taps are injected as short single-finger events.

The optional magnetic-dock CDC-ACM console is disabled so ESP-EMU's UART0 remains the bidirectional KodeOS console. The browser sends UTC wall-clock updates through the native `time set=` command and reads the clock state back.

## Real display pixels

The screen is **not** generated by this virtual part or by an HTML mockup. The pinned KodeOS/KGUI firmware renders into two RGB565 PSRAM framebuffers through the simulator-only headless display overlay.

The build exports the framebuffer pointer and sequence symbols from the real firmware ELF. The browser uses ESP-EMU's `read_memory(addr, len)` API to read coherent framebuffer snapshots directly from emulated PSRAM, then converts those RGB565 bytes into the 410×502 canvas. The canvas is only the display surface for pixels produced by KGUI.

## Scope and limitations

This is not a complete hardware model. It does not yet implement the CO5300 MIPI-DSI controller, SD card, IMU, NFC/RFID, audio codec, haptics, IR or a separately emulated ESP32-C5. Unsupported devices remain unsupported rather than returning invented sensor data.
